# Mini Skill & Competency Graph

This project takes the SkillsFuture dataset and turns it into a graph. With the graph, we can answer the kind of questions a learner actually asks, for example:

- "What skills do I need to become a Data Scientist?"
- "I know Python and SQL. What is the fastest way to become an AI Engineer?"
- "Which Digital skills can I bring with me to the Green economy?"

I built four things on top of the graph:

1. **Gap Analysis.** You tell it your skills and the role you want. It tells you which skills you are missing, which one to learn first, and which course to take for each.
2. **Learning Path.** It puts the missing skills in the right order (you can't learn Deep Learning before Machine Learning), groups them into stages, and picks the set of courses that covers everything in the fewest hours.
3. **Ask in plain English.** You type a question, Gemini works out what you are asking, the graph finds the answer, and Gemini writes the reply. The reply is checked against the graph before you see it, so it can't make up a course.
4. **Graph explorer (bonus).** A web page where you can see the whole graph, click around, and watch a learning path drawn on it.

The stack is Python, NetworkX for the graph, FastAPI for the API, and Gemini for the language part. Everything also works without an API key. In that case a simple rule-based parser reads the questions instead of Gemini.

## Getting started (about 5 minutes)

Python 3.11 or newer.

```bash
git clone <repo-url> skill-graph && cd skill-graph
python3 -m venv .venv && source .venv/bin/activate
pip install -e ".[dev]"
```

Run:

```bash
skillgraph validate                    # load the data and show the data-quality report
skillgraph learners                    # the 3 sample learners in the dataset
skillgraph gap  --learner LP-01        # gap analysis for Alex
skillgraph path --learner LP-02        # learning path for Priya
pytest                                 # 110 tests, about 1 second, no internet needed
```

**To use Gemini for the questions.** This part is optional. A free key from Google AI Studio is enough.

```bash
cp .env.example .env                   # then put your key in .env as GEMINI_API_KEY
skillgraph ask "I know Python and SQL. What's the fastest path to AI Engineer?" --trace
```

If you use Vertex AI instead of an API key, set `SKILLGRAPH_VERTEX_CREDENTIALS` in `.env` to the path of your service-account file. The `--trace` flag shows each step the question went through.

**To open the web explorer and the API:**

```bash
skillgraph serve                       # then open http://127.0.0.1:8000
```

The API documentation is at http://127.0.0.1:8000/docs, where you can try every endpoint in the browser.

**Or run everything in Docker,** with no Python setup:

```bash
docker build -t skillgraph .
docker run -p 8000:8000 --env-file .env skillgraph     # leave out --env-file to run without Gemini
```

## Gap Analysis

```bash
skillgraph gap --learner LP-02
skillgraph gap --skills "Python, SQL" --role "Data Scientist"
```

You can type skills and roles the way you would say them. "pyton", "ai engineer" and "SKL-04" all work. If a name could mean more than one thing, like "data analyst" (there are three analyst roles), it asks you which one instead of guessing.

Here is the result for Priya (LP-02). She is a junior developer who wants to become an AI / Machine Learning Engineer:

| Rank | Missing skill | Priority | Why | Suggested course |
|--:|---|---|---|---|
| 1 | Machine Learning | High (66) | Unlocks 3 of her other missing skills (Deep Learning, Generative AI, MLOps). National priority skill. | Machine Learning Fundamentals (NTU PaCE, 60 h) |
| 2 | Generative AI | Medium (50) | National priority skill. Needed by 2 of the 18 roles. | Generative AI for Business (SMU Academy, 16 h) |
| 3 | AI Ethics & Governance | Medium (45) | National priority skill. | Responsible AI & Governance (AI Singapore, 24 h) |
| 4 | MLOps | Low (35) | She needs Machine Learning first. | MLOps & Model Deployment (NUS-ISS, 32 h) |
| 5 | Deep Learning | Low (25) | She needs Machine Learning first. | Deep Learning & Neural Networks (NUS-ISS, 40 h) |


**What "priority" means here.** It means "what should I work on first", not "how important is this skill". The dataset README talks about a Core/Supporting importance on each skill, but the data doesn't have it. So I score priority from the graph itself, using four things:

- How many of the learner's other missing skills this one unlocks.
- Whether it is a national priority skill (SDFE).
- How many roles need it.
- Whether the learner already has what it requires.

Every skill comes with its reasons, so you can see why it got its score. That's why Deep Learning is Low for Priya. It matters for the role, but she can't start it until she knows Machine Learning.

## Learning Path

```bash
skillgraph path --learner LP-02
skillgraph path --skills "Python, SQL" --role "AI Engineer"
```

For Priya, the path has three stages. Skills in the same stage don't depend on each other, so she can learn them at the same time:

1. **Stage 1:** Statistical Analysis, AI Ethics & Governance
2. **Stage 2:** Machine Learning (it needs Statistical Analysis)
3. **Stage 3:** Generative AI, MLOps, Deep Learning (they all need Machine Learning)

Then it picks the courses. The plan is **172 hours** in total, or **100 hours** if she takes courses in the same stage at the same time. No other set of courses covers her missing skills in fewer hours. The tests check this against every possible combination.

There are two modes:

- **`fastest`** (the default) only adds a prerequisite when it is really required.
- **`thorough`** also adds the ones the data only recommends. For example, Generative AI before Prompt Engineering.

The full outputs for all three sample learners are in [docs/examples/offline/](docs/examples/offline/).

## Asking in plain English

```bash
skillgraph ask "What skills do I need to become a Data Scientist?"
skillgraph ask "I know Python and SQL. What's the fastest path to AI Engineer?"
skillgraph ask "Which Digital skills are most transferable to the Green economy?"
```

All three required question types work. So do the two extra types in the dataset's sample questions: gap analysis when you give your current job instead of your skills, and "which course should I take to learn X".

**How a question gets answered.** There are four steps:

1. **Understand the question.** Gemini reads the question and fills in a fixed form: what kind of question it is, which role, which skills, which economies. It only writes down the words the user used. It never looks up ids.
2. **Find the real things.** My code matches those words to real skills and roles in the graph. If a name matches nothing, or matches several things, the user gets a question back instead of a guess.
3. **Run the query.** This is the same gap analysis or learning path code that the command line and the API use.
4. **Write the reply.** Gemini writes the answer using only the query result. Then I check the answer: every course, skill and number in it must be in the result. If anything isn't, the user gets a plain template answer instead.

The idea behind this split is simple. Gemini is good at understanding language but can make things up. The graph is exact but can't read English. So Gemini only does the language parts, and the facts always come from the graph.

If there is no API key, or Gemini fails, the rule-based parser and template answers take over. You always get an answer.

### How well it understands questions

I wrote two sets of test questions:

- **Development set (32 questions).** I used these while building, including to write the rule-based parser.
- **Held-out set (12 questions).** I wrote these separately and never tuned anything on them. They show how the system handles wording it hasn't seen.

A question counts as correct when the system picks the right kind of question and finds the right role, skills and economies. Wording doesn't matter. Asking back on an unclear name also counts as correct when that is the right thing to do.

```bash
skillgraph eval            # uses Gemini if a key is set
skillgraph eval --offline  # rule-based parser only
```

| Parser | Development (32) | Held-out (12) |
|---|--:|--:|
| Rule-based (offline) | 100% | 50% |
| Gemini (`gemini-3.8-flash`, on Vertex AI) | 100% | 100% |

What this tells us:

- The rule-based parser gets 100% on the questions I wrote it for, but only 50% on new ones. That is overfitting, and it is exactly why the LLM is there.
- Gemini got every question right in both sets. Nothing fell back to the rule parser.
- None of Gemini's 37 written answers failed the fact check. The other 7 questions were unclear or off-topic, so they got a standard reply by design.
- The sets are small. Getting 12 out of 12 means I found no failures, not that the problem is solved. Statistically, the true accuracy could still be as low as about 74%.
- One question takes about 9 seconds with Gemini (two calls). Repeated questions come from a local cache and are instant.

You can read the real answers in [docs/examples/llm/nl_queries.md](docs/examples/llm/nl_queries.md) (Gemini) and [docs/examples/offline/nl_queries.md](docs/examples/offline/nl_queries.md) (no API key).

## Graph explorer

Run `skillgraph serve` and open http://127.0.0.1:8000. You can:

- **See the whole graph.** All 123 nodes, filtered by type. Prerequisites are orange lines, and dashed when they are only recommended.
- **Click any node** to see its details and connections.
- **Draw a learning path.** Pick a sample learner or type some skills, and the path appears on the graph, numbered in learning order.
- **Ask a question.** The same plain-English feature, with the steps it went through.
- **See skill demand.** The skills most roles need, and the needed skills that have no course.

## How the code is organised

```
src/skillgraph/
  models.py            the dataset's data models
  ingest/              load the JSON and check it (the data-quality report)
  graph/               the graph schema, the NetworkX store, and the Neo4j export
  services/            name matching, prerequisites, course planning, the queries
  nl/                  everything for plain-English questions: prompts, Gemini, rule parser, checks, evaluation
  api/app.py           the REST API
  cli.py               the command line
  viz/static/          the graph explorer (one HTML page)
data/                  the dataset, unchanged
eval/                  the test questions (development and held-out)
scripts/               regenerates docs/examples
tests/                 the test suite
docs/                  all documents
```
